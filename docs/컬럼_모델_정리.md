## 2. 모델 학습 피처 — 9개

**원칙: 승차 시점에 알 수 있는 것만 쓴다.**

### 수치형 5개 (`NUMERIC_FEATURES`)
```
hour, dow, is_weekend, trip_distance, passenger_count
```

### 범주형 4개 (`CATEGORICAL_FEATURES`)
```
PULocationID, DOLocationID, VendorID, RatecodeID
```

> 존 ID는 정수로 저장돼 있지만 **숫자 크기에 의미가 없는 명목형**이라 범주형으로 취급했다.
> 그냥 수치로 넣으면 "존 132가 존 66의 2배"라는 잘못된 관계를 모델이 학습한다.

### 일부러 뺀 컬럼 — 여기가 핵심

| 제외 컬럼 | 이유 |
|---|---|
| `duration_min` | **타깃 그 자체.** 속도 = 거리 ÷ 시간이므로 넣으면 정답을 알려주는 것 |
| `speed_mph` | 타깃 계산의 원본 |
| `fare_amount` | NYC 요금은 거리+시간 기반 → 소요시간이 새어 들어감 |
| `tip_amount`, `total_amount` | 하차 후에야 확정 |

**조원 확인 포인트** : 각자 모델에서 위 컬럼을 피처에 넣었다면 성능이 비정상적으로 높게 나옵니다. F1이 0.9를 넘으면 누수를 의심하세요.

## 3. 타깃 2종

같은 "정체"라도 정의에 따라 잡히는 현상이 달라서 **두 개를 만들어 비교**했습니다.

| | `jam_abs` 절대정체 | `jam_rel` 상대정체 |
|---|---|---|
| 정의 | 전체 트립 평균속도 **하위 33%** | **동일 경로**(출발존→도착존) 평소 중앙속도 대비 하위 33% |
| 임계값 | **7.05 mph** 미만 | 평소 속도의 **86.4%** 미만 |
| 정체 비율 | 33.3% | 33.3% |
| 전제 조건 | 없음 | 표본 30건 이상인 경로 5,078개만 사용 |

두 정의가 같은 판정을 내린 비율은 **81.5%** 입니다.

### 두 정의가 실제로 잡는 트립이 다릅니다

| | 중앙 거리 | 중앙 소요 | 중앙 속도 | **1마일 미만 비중** |
|---|---|---|---|---|
| 절대정체 | 1.18 mi | 14.17분 | 5.43 mph | **39.2%** |
| 상대정체 | 1.50 mi | 17.95분 | 5.62 mph | **29.5%** |

절대정체로 분류된 트립의 **39%가 1마일도 안 됩니다.** 맨해튼 도심 크로스타운은 교통 상황과
무관하게 원래 느리기 때문입니다. 즉 절대정체는 "교통 정체"뿐 아니라 **"도심 단거리라는 트립
성격"을 함께 잡습니다.** 상대정체는 경로별 평소 속도를 기준으로 삼아 이 성격을 통제합니다.

## 4. 모델

### 파이프라인 구조

```
Pipeline
 ├─ preprocess : ColumnTransformer
 │   ├─ numeric     (5개 컬럼) : SimpleImputer(median) → StandardScaler
 │   └─ categorical (4개 컬럼) : SimpleImputer(most_frequent) → OneHotEncoder
 └─ classifier : RandomForestClassifier
```

전처리를 Pipeline **안에** 넣어야 학습 데이터에서 구한 통계값(중앙값·평균·분산)이 테스트
데이터에 그대로 적용됩니다. 밖에서 미리 전처리하면 테스트 정보가 학습에 새어듭니다.

### 하이퍼파라미터

| 항목 | 값 | 비고 |
|---|---|---|
| 모델 | `RandomForestClassifier` | |
| `n_estimators` | 100 | |
| `min_samples_leaf` | **5** | 기본값 1이면 모델 파일이 636MB. 5로 두면 55MB이면서 F1도 0.7606→0.7651로 **개선** |
| `random_state` | 42 | 재현성 |
| `n_jobs` | -1 | 전 코어 사용 |
| `OneHotEncoder.min_frequency` | 50 | 표본 적은 존을 묶어 차원 폭발 방지 |
| `OneHotEncoder.handle_unknown` | `infrequent_if_exist` | 미학습 범주 대응 |

### 학습 설정

| 항목 | 값 |
|---|---|
| 학습 표본 | 200,000행 (정제 후 284만 행에서 추출) |
| 분할 | 8 : 2 홀드아웃, `stratify=y` |
| 기준선 | `DummyClassifier(strategy="most_frequent")` |
| 전처리 후 피처 수 | 약 190개 (원-핫 인코딩 결과) |

## 5. 결과

| 타깃 | 정확도 | F1(macro) | 기준선 F1 | **F1 개선** | 학습 시간 |
|---|---|---|---|---|---|
| `jam_abs` 절대정체 | 0.7964 | **0.7651** | 0.3966 | **+0.3685** | 3.5초 |
| `jam_rel` 상대정체 | 0.7339 | 0.6575 | 0.4002 | +0.2573 | 3.6초 |

> **정확도만 보면 안 됩니다.** 클래스가 불균형해서 아무것도 안 배운 기준선도 정확도 0.66이
> 나옵니다. **F1(macro) 개선폭**을 봐야 모델이 실제로 학습했는지 판단할 수 있습니다.

**절대정체가 점수는 높지만 좋은 가설이라는 뜻은 아닙니다.** 그 차이의 상당 부분은
"도심 단거리인지"를 맞히는 데서 옵니다. 상대정체는 점수가 낮아도 "평소보다 막혔다"는
의미에 더 충실합니다.
